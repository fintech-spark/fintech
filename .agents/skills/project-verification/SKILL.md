# Project verification

`npm run verify:setup` = `lint && typecheck && test && build`. That is the floor, not the ceiling.

## Commands

| Command | What it proves | Notes |
|---|---|---|
| `npm run lint` | ESLint clean | |
| `npm run typecheck` | `tsc --noEmit` | catches most integration breakage |
| `npm test` | 48 files, 1061 tests | **29 skip without a database** |
| `npm run build` | Next production build; route handlers type-checked | |
| `npm run test:db` | static schema + Zod validation | no DB required |
| `npm run test:db:live` | live RLS/DDL tests | needs `DATABASE_URL`, fails loudly without it |
| `npx vitest run tests/database-security.test.ts` with `LOCAL_DATABASE_URL` | **cross-tenant denial** | the strongest isolation evidence in the repo |
| `npm run test:e2e` | Playwright journeys | needs `npm run test:e2e:install` first |
| `npm run eval` | AI eval gate | offline only; currently runs **one** file |
| `npm run security:audit` | `npm audit --audit-level=high` | prod deps only |

## The skip trap

`tests/database-security.test.ts:9` does `const describeDb = LOCAL_DATABASE_URL ? describe : describe.skip`.
Without that variable the entire cross-tenant suite is silently skipped and `npm test` still reports
green. **A green suite is not evidence of tenant isolation** unless you ran it with the variable set:

```bash
LOCAL_DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres \
  npx vitest run tests/database-security.test.ts
```

Never report isolation as verified on the strength of a default `npm test`.

## CI reality

`.github/workflows/`: `ci.yml` (lint/typecheck/test/build + local Supabase stack → `db:migrate` →
`tests/database-security.test.ts`), `security.yml` (npm-audit, dependency-review, **gitleaks**),
`codeql.yml`, `semgrep.yml`, `e2e.yml` (pull_request), `ai-evals.yml` (manual `workflow_dispatch`
only — provider-backed evals are not in the default gate).

## Gotchas

- **One `next dev` per directory.** Next holds a `.next` lock; a second dev server on another port
  refuses to start. Kill the first, or run `next build` after stopping dev.
- `next build` while `next dev` is running corrupts `.next`. Stop dev first.
- `next-env.d.ts` is regenerated by every dev/build run and shows up as a dirty file. Do not commit
  it reflexively; decide once whether it stays tracked.
- The local Supabase stack runs on `127.0.0.1:54321` (API) / `54322` (DB); `npx supabase status
  --output env` prints the local anon key when you need to exercise auth without hosted credentials.
- 3 migrations are still pending on the hosted database (`20261002000009/10/11`): run
  `npm run db:migrate:status`.
- `npm run eval` executing one file is not a passing AI evaluation. Say so.

## Reporting rules

State what you actually ran, with the command and the result. Distinguish pre-existing failures
from ones you caused, and environment failures from real ones. "I did not verify this" is a valid,
expected answer; a confident claim about an unrun check is not.

## Definition of done

```bash
npm run lint && npm run typecheck && npm test && npm run build
```

plus, for anything touching data or isolation:
`npm run test:db` and the `LOCAL_DATABASE_URL` security suite.
